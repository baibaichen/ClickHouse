## 2. Method and authority

- **Behavior oracle** is current ClickHouse `src/` + real callers. Task docs, receipts, decisions, prior reviews, tests, logs, and mutations are **evidence/intent, never the oracle**.
- **Read-only.** Production code in both repos was not modified. The only artifact written is this file; scratch under `/root/oss/clickhouse/tmp` only.
- **Frozen baseline authority.** Accepted intent for design/task/review docs is their state at accepted ClickHouse HEAD `92707bea404` (read via `git show HEAD:<path>`). Any concurrent **uncommitted** working-tree edits to forward docs made by other processes in this shared environment are **not** accepted baseline and are excluded from scoring (see §11.7).
- **Classification rules applied.** Allowed statuses: `MATCH`, `EQUIVALENT`, `INTENTIONAL_DEVIATION`, `MISSING`, `UNPROVEN`.
  - `INTENTIONAL_DEVIATION` only where the differing behavior/guarantee was explicitly approved or conditionally accepted.
  - Any unapproved guarantee-changing replacement — **including any root-oss/2 D1–D8 item that materially governs the row** — is `UNPROVEN` even if current output tests pass.
  - For a differing lock/container/state/ownership primitive, `MATCH`/`EQUIVALENT` requires the deviation to be in an **approved** structural-deviation ledger; otherwise `UNPROVEN`.
- **Test evidence** cites the exact current Velox test **source** (repo-relative `file:line` + `Suite.Name` + CTest target), resolved from a full index of all 427 test cases. No test was executed in this phase; instead a read-only `ninja -n`/plan dependency check proved all 15 `velox_ch_*` test binaries are dependency-up-to-date with the current clean tree (= HEAD `43a9e6f75`) — see §11. Mutation/RED evidence cites the exact receipt/log `path:line` (or explicitly "none"); receipt pass-counts remain **historical** (recorded at the receipts' Velox heads).
